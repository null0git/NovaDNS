Every cache entry stores its origin (authoritative vs. forwarded) alongside the answer. This is what lets a cache hit still set the DNS AA bit correctly — a cached authoritative answer is still authoritative; a cached forwarded answer never is.

Query arrives
→
cache.get(name, type)
→
HIT: return + true origin
MISS
→
resolve from zone/forwarder
→
cache.set(..., origin=authoritative|forward)

TTL comes from the lowest TTL among the returned records (or the zone's negative-TTL for NXDOMAIN). Eviction is a simple oldest-5% sweep when the cache exceeds its entry cap — no LRU bookkeeping overhead on the hot path.

→
Sign every RRset (RRSIG)
→
Serve on EDNS DO=1

Each RRSIG covers a canonical wire-format encoding of its RRset per RFC 4034 §6: owner name lowercased and uncompressed, RRs sorted by RDATA when there's more than one. The signature itself is raw r‖s (64 bytes for P-256), not DER — per RFC 6605. Editing a record on a signed zone triggers an automatic full re-sign.

One process, several long-lived threads plus per-request worker threads:

Main threadFlask/Werkzeug dev server (or a WSGI server in production)
novadns-udpaccepts UDP packets, spawns a worker thread per packet
novadns-tcpaccepts TCP connections, spawns a worker thread per connection (AXFR, DoT-forwarded lookups, large responses)
novadns-alertspolls health every 30s, dispatches notifications
novadns-blocklistsrefreshes subscribed blocklists every 24h

Each thread that touches SQLite gets its own thread-local connection (WAL mode + busy-timeout), so a burst of concurrent queries from many devices never blocks on a single shared connection.
